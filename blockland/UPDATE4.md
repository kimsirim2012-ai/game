# 4차 업데이트: 1~4단계 개발 기록

## 수정 전 분석

외부 라이브러리가 없는 자체 WebGL 1 엔진을 사용한다. 기존 `game.js`의 아틀라스/청크 메시/DDA 선택/입력/저장 연결, `physics.js`의 120Hz 물리와 swept AABB, `world.js`의 16×16×112 동적 청크/노이즈 지형/식물/마을, `ecosystem.js`의 동물 9종/주민 모델과 거리별 AI, `environment.js`의 낮밤/안개/소리, `storage.js`의 IndexedDB를 재사용한다.

기존에는 블록 수가 무제한이며 클릭 즉시 파괴/설치한다. E는 창작 블록 선택과 식물 수집량만 표시한다. 도구, 무기, 인벤토리 스택, 드롭 엔티티, 제작, 엔티티 체력, 공격, 몬스터는 없다. 생존용 허기/낙하/익사/방어구/경험치도 없다.

렌더링은 청크 배치, 이웃 면 제거, Frustum Culling, 생성/메시 작업 분산을 적용한다. 개체 모델은 30Hz 배치, AI는 거리별 4~20Hz이며 전체 76개로 제한한다. 수백만 블록을 매 프레임 순회하지 않도록 캐시된 통계를 유지한다. 투명 면의 정렬은 청크 단위이고 장거리 길찾기/Greedy Meshing/Worker는 아직 없다.

재사용 방침: 기존 엔진·월드 높이·바이옴과 블록 편집 기록을 유지한다. 새 자원/아이템/전투를 별도 모듈로 추가하고, 예전 저장은 창작 모드로 읽는다. 이번 범위는 1~4단계다. 허기 등 본격 생존과 신규 지형/던전/보스는 후속 단계로 구분한다.

## 1단계: 호환성·오류 수정

기존 무제한 건축은 창작 모드로 보존하고 유한 아이템 모험 모드를 추가했다. v1/v2는 창작으로 가져온다. 낮은 FPS에서 개체 시간만 0.1초로 잘리던 차이를 물리의 0.25초 상한과 맞췄다. 프레임 정지 후 무제한 시간 보충은 하지 않는다. 드롭·화살의 60Hz 누적기에는 부동소수점 경계 허용치를 적용해 15FPS와 144FPS에서 한 틱 차이가 생기는 문제도 수정했다.

축과 평행한 DDA 광선에서 0×Infinity로 NaN이 생기는 경계 문제를 방지했다. 전투 판정은 식물 대신 고체 블록을 가림막으로 사용한다. 모험의 빈손 우클릭이 기존 무제한 설치 경로로 넘어가지 않게 막고, 주민·제작대·화로 상호작용의 우선순위를 정리했다.

옛 버전 탭이 새 인벤토리를 덮어쓰지 않도록 v3 저장 키를 분리했다. 유효한 새 포맷을 우선하고 포맷 안에서 저장 시각으로 최신본을 고른다. 잘못된 JSON·스택·내구도·체력은 현재 세상을 교체하기 전에 거부한다. 원래 64×64 코어의 전체 복셀 해시가 기존 스냅샷과 일치하며, 기존 편집 기록 형식을 유지했다.

## 2단계: 도구

나무·돌·철·다이아몬드별 곡괭이·도끼·삽·괭이·검 총 20종을 데이터로 정의했다. 종류별 채굴 보너스와 재료별 등급·속도·내구도를 사용한다. 검은 도끼보다 빠르고, 도끼는 한 번의 피해가 크다. 도구는 내구도 0에서 파손된다. 빗나간 공격은 내구도를 소비하지 않는다.

돌은 곡괭이가 있어야 조약돌이 나오고, 철은 돌 곡괭이 이상, 다이아몬드는 철 곡괭이 이상이 필요하다. 맨손·잘못된 도구로도 시간을 들여 제거할 수 있지만 해당 광물 드롭은 얻지 못한다. 도끼는 나무, 삽은 흙·모래·자갈에 빠르다.

괭이 우클릭은 흙·잔디를 경작지로 바꾼다. 가위는 양털과 잎·풀 수집에 쓰인다. 낚싯대는 물에 찌를 던지고 5~9초 뒤 입질 때 3초 안에 다시 우클릭하면 생선을 얻는다. 작물·번식·음식 섭취는 이번 범위 밖이다.

## 3단계: 드롭·채집·제작

- 경도와 도구에 따른 시간만큼 좌클릭을 유지해 채굴한다. 중단·대상 변경 시 진행이 초기화되고 단계별 균열·파티클·효과음이 나온다.
- 실제 드롭이 중력으로 떨어지고 가까이 가면 수집된다. 가방이 가득 차면 남은 아이템을 바닥에 둔다. 설치는 소지 수량을 소비하며 몸 안에는 놓지 못한다.
- 36칸 인벤토리, 9칸 핫바, 일반 스택 64개, 개별 도구 내구도, 클릭·절반 이동·Shift 이동·드래그·G 버리기를 구현했다.
- 판자·막대기·제작대·20종 도구·화로·활·화살·방패·가위·낚싯대 제작법을 추가했다. 제작은 복사본에서 재료와 출력 공간을 확인한 후 한 번에 적용한다. 공간 부족 시 재료만 사라지지 않는다.
- 설치한 제작대 주변에서 고급 제작이 가능하다. 수동 2×2/3×3 격자는 아직 없으며 재료를 소비하는 제작법 목록 방식이다.
- 지하 돌 일부에 시드 기반 석탄·철·다이아몬드 광맥을 추가했다. 기존 64×64 코어와 편집 블록은 보존했다. 새로운 바이옴이나 높이 생성식 변경은 이번 범위 밖이다.
- 실제 화로 우클릭 UI에서 원석·석탄을 소비해 제련한다. 철 1개당 8초, 석탄 1개당 최대 8개이며 인벤토리를 열어 둬도 진행된다. 진행 중 화로 파괴 시 원석, 완료 후 파괴 시 철괴가 나온다. 연료 슬롯·음식 조리는 후속 작업이다.

## 4단계: 전투와 기본 몬스터

- 조준 광선과 개체 AABB로 근접 대상을 고르며 고체 블록 뒤나 3.15블록 밖의 적은 맞지 않는다. 무기별 피해·공격 간격·넉백·피격 색상·사망 연출·전리품을 적용했다. 주민은 공격 대상에서 제외했다.
- 기존 WebGL에 1인칭 손·장비, 공격·채굴 모션, 활 장전, 화살, 방패를 연결했다. 그래픽·효과음은 자체 절차 생성이며 원작 에셋은 사용하지 않았다.
- 활은 우클릭 유지 후 놓을 때 화살 1개와 내구도를 소비한다. 화살에 중력·구간 충돌을 적용해 얇은 벽을 뚫지 않는다. 블록에 박힌 플레이어 화살은 회수용 드롭이 된다.
- 방패는 E의 버튼으로 보조 손에 장착한다. 정면 화살을 막고 정면 근접·폭발 피해를 줄인다. 뒤쪽 공격은 통과하며 방패 내구도를 소비한다. 방어 중에는 근접 공격하지 못한다.
- 좀비는 근접, 스켈레톤은 거리 유지·화살, 크리퍼는 접근·점멸·1.5초 도화선 후 폭발, 거미는 빠른 근접 공격을 사용한다. 폭발은 최대 70블록만 수정하고 월드 바닥을 보존한다.
- 밤·지하 생성 조건, 주기적 생성 시도, 몬스터 최대 12·전체 최대 76, 멀어진 개체 정리, 가까운 AI 20Hz·먼 AI 5Hz를 적용했다. 밝은 지상에서 좀비·스켈레톤은 화상을 입는다.
- 실제 전투를 위해 체력 20·피격·사망·소지품 드롭·리스폰·일시 무적도 연결했다. 동물도 체력과 종류별 기본 전리품을 갖는다. 완전한 5단계 생존 시스템까지 구현한 것은 아니다.

AI는 충돌 물리, 짧은 전방 검사, 옆 방향 선택과 점프를 사용한다. 미로·절벽을 해결하는 A* 길찾기는 없다. 공격 수치·실루엣·행동은 자체 단순화로 원작과 정확하게 같지 않다. 모험에도 기존 비행·시작점 복귀 조작을 유지했다.

## 저장과 부하 제한

JSON은 version:3, 월드 생성기는 기존 generator:2를 유지한다. IndexedDB BlocklandExploration/worlds/current-v3, 작은 localStorage 복구본 blockland.adventure.v3를 사용한다. 기존 current와 v1/v2 키는 읽되 새 인벤토리로 덮어쓰지 않는다.

월드·위치·시간·인벤토리·내구도·방패·체력과 함께 드롭·화로 진행·재생성 대기 기록·주변 살아 있는 몬스터의 ID/종류/체력/위치를 저장한다. 화살 비행·공격 쿨다운·크리퍼 도화선·파티클은 재접속 시 초기화된다. 동물·주민의 장기 위치·체력·털 상태 저장은 아직 없다.

드롭 레코드 최대 2,048개, 근처 드롭 물리 약 160개·렌더링 최대 128개, 화살 48개, 파티클 160개, 화로 작업 64개로 제한한다. 드롭 한도 시 추가 채굴을 멈춰 해당 블록을 보존한다. 멀리 있는 드롭은 휴면 상태로 저장한다. 기존 청크 면 제거·배치·거리별 AI·언로드를 재사용했다. Greedy Meshing·Worker·전면 InstancedMesh 전환은 이번에 추가하지 않았다.

빈 가방에서 나무를 모아 제작대와 도구를 얻는 과정을 실제 플레이 입력으로 검사했다. 밤의 자연 몬스터 생성도 별도로 검사했다. 활·방패·검의 반복 가능한 전투 검증은 준비된 장비와 저장된 몬스터가 있는 테스트 세상을 가져와 수행했다. 모든 광물을 탐험해 모든 장비를 맨손부터 제작하는 장시간 플레이를 완료한 것은 아니다.

가위·괭이·낚시, 몬스터 세부 피해·화살·폭발, 등급·파손·드롭 넘침은 단위 검사로 확인했다. 각 항목 전부를 별도의 수동 브라우저 플레이로 확인한 것은 아니다. OS가 처리하는 Ctrl+W 단축키의 실제 차단은 자동 검사 범위 밖이다.

### 성능

Chrome headless / ANGLE SwiftShader / 1280×720 / 렌더 반경 5(80m)에서 청크와 메시 생성이 끝난 뒤 115프레임을 측정했다. 평균 **59.48 FPS / 16.81ms**, p95 **16.70ms**였다. 당시 청크 97개, 복셀 데이터 2.65MiB, 동물·주민 55개, draw call 78개였다. 원시 결과는 tests/performance-results.json이다.

시작 지점 정지 상태 측정이다. 몬스터 무리·폭발·이동 중 로딩·최대 거리·모든 PC의 60FPS를 보장하지 않는다. 생성 중 프레임 시간이 길어질 수 있으며 메뉴 렌더 거리와 F3 진단으로 조절한다.

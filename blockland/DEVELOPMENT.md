# Blockland 개발 기록

## 시작점 전체 분석 — 2026-10-17

- 전체 프로젝트: `Blockland.html` 단일 HTML/CSS/JS 파일과 `work/verify.cjs` 검증 스크립트. 외부 라이브러리, Three.js, 빌드 의존성 없음. 자체 WebGL 1 셰이더와 행렬 계산을 사용함.
- 월드: 64×36×64 Uint8Array, 16×16 수평 청크 16개. 고정 크기의 시드 기반 삼각함수 지형, 물과 나무. 공기와 물을 구분하는 충돌 판정. 원작 게임 자산 없이 자체 생성 텍스처.
- 렌더링: 텍스처 아틀라스/NEAREST, 블록 윗면·옆면, 이웃 면 제거, 청크별 GPU 버퍼, 고정 주변광·안개, 선택 테두리. 최초 시드에 30,738개 블록, 91,692개 정점. 매 프레임 16개 청크 모두 제출. Greedy Meshing/Frustum Culling/Worker 없음.
- 조작: Pointer Lock, WASD/마우스, 점프, Shift 달리기, F 비행, 8칸 핫바, 단발 채굴/설치. 무제한 블록을 사용하는 창작 모드. 생존 기능은 아직 없음.
- 저장: `blockland.offline.v1` localStorage 키 하나. version/seed/edits/눈 위치/시점/flying/selected JSON. 수정 블록의 선형 인덱스 기록. 0.5초 디바운스·10초 간격·종료/메뉴 저장, JSON 내보내기/가져오기. 파일 경로와 브라우저별 저장 영역 차이가 있으므로 기존 바탕화면 경로 유지.
- 기존 회귀 검증: 렌더링, 잠금, 이동, 비행·상승, 핫바, 파괴, 설치, 메뉴, 자동 저장·재개, 파일 내보내기·가져오기 11개 통과.

## 발견한 문제와 우선순위

1. 물리가 가변 프레임 dt에 종속되고 dt를 0.05초에서 버려 저FPS에서 게임 시간이 느려짐.
2. 0.15블록 이동 시도 단위로 충돌 시 전체 단계를 취소하여 바닥·벽에 정확히 밀착하지 못함. 눈 위치 기반 상자에 수치 허용오차도 없음. 높은 낙하 속도에 대한 명시적 swept AABB 없음.
3. 공중 제어/가속/감속이 없음. Shift가 달리기이며 웅크리기·가장자리 보호·수영이 없음.
4. 모든 청크를 매 프레임 그림. 블록 수정 시 최대 3개 청크 메시를 동기 재생성. 레이캐스트가 매 프레임 최대 약 200회 조회하며 선택 테두리 CPU/GPU 배열도 매 프레임 다시 작성함.
5. 저장 위치가 블록과 겹치면 탈출 처리가 없고, 불러오기 후 물리 상태 초기화가 제한적. WebGL 문맥 유실 복구 없음.
6. 생존 인벤토리·제작·엔티티·조명·무한 청크·IndexedDB는 아직 구현되어 있지 않음. 존재하는 기능처럼 표시하지 않음.

기존 엔진으로 요청한 1·2단계를 충분히 구현할 수 있음. 엔진 교체나 월드 포맷 변경 없이 진행. 이후 확장 순서는 블록/아이템 → 동적 월드 → 조명 → 인벤토리/제작 → 생존 → AI → 저장/추가 최적화.

## 1단계 완료 — 구조 정리와 핵심 수정

- 기존 HTML을 `src/Blockland.template.html`과 `src/game.js`로 분리. 새 물리는 DOM/WebGL에 의존하지 않는 `src/physics.js`. `node build.cjs`로 단일 오프라인 `Blockland.html` 생성. 서버·다운로드·런타임 라이브러리 없이 기존 바탕화면 파일 실행 방식 유지.
- 시드/블록 ID/선형 인덱스/저장 키/version 1 형식 유지. 기존 파일을 읽고 눈 위치를 발 위치로 변환. 저장 위치가 블록에 파묻혔으면 위쪽 안전한 공간으로 보정. JSON 가져오기 검증 강화.
- 선택 레이캐스트를 작은 간격 샘플링에서 복셀 DDA로 변경. 선택 테두리는 대상 좌표가 바뀔 때만 GPU 버퍼 갱신.
- Frustum Culling, 뒷면 제거, 블록 수정 시 중복을 합친 청크 메시 큐 적용. 한 프레임에 최대 한 청크를 다시 만듦. 이는 동적 청크 로딩/Greedy Meshing 구현과 별개이며 월드는 여전히 고정 크기.
- FPS 상시 표시, F3에 프레임 시간·그려진 청크·Draw Call·메시 생성 시간·물리 상태 표시.

## 2단계 완료 — 조작·물리·충돌

- 초당 120회 고정 물리, 잔여 시간 누적, 렌더링 보간. 탭 중단 시 최대 0.25초만 따라잡고 버린 시간을 진단에 표시. 숨김/초점 상실/메뉴에서 입력 초기화와 물리 일시 정지.
- 발 위치 기반 AABB: 폭 0.6, 서 있을 때 키 1.8, 눈 높이 1.62. 웅크리기 키 1.5/눈 1.27. 수치 오차를 허용하는 축별 swept collision으로 벽/바닥/천장에 정확히 접촉.
- 속도 목표(블록/초): 걷기 4.317, 달리기 5.612, 웅크리기 1.295, 물속 2.2. 지상 가속/감속, 약한 공중 제어, 대각선 정규화. 점프 높이는 약 1.25블록을 목표로 조정. 이는 Java Edition의 틱/마찰 모델을 그대로 복제한 것이 아닌 근사 물리임.
- Shift 웅크리기, 발판 가장자리 보호, 머리 위 공간이 없으면 일어설 수 없음. 물속 부력/저항/상승·하강, 머리 잠김 판정과 수중 화면.
- WASD/마우스/Space/E/Esc/1~9/휠, Ctrl+W 및 W 두 번 달리기, 기존 F 비행과 Q 하강/R 시작점 복귀 유지.
- 카메라 눈 높이 전환 보간, 작은 걷기 흔들림, 달리기 FOV 전환. 카메라 흔들림은 물리 상자에 영향 없음.
- 9칸 핫바의 9번에 기존 물 블록 연결. E는 실제 현재 블록 9종을 선택하는 **창작 블록 선택창**임. 생존용 36칸 인벤토리·아이템 수량·제작은 아직 미구현.
- Ctrl+W는 창 모드에서 브라우저의 탭 닫기 예약 키와 충돌할 수 있음. 메뉴의 전체 화면 옵션은 Fullscreen + Keyboard Lock API로 KeyW 조합을 요청하고, 메뉴/선택창/전체 화면 종료 때 해제. 권한을 얻지 못하거나 API가 없으면 W 두 번 사용. 근거: [Chrome Keyboard Lock 문서](https://developer.chrome.com/articles/keyboard-lock). Esc 자체를 잠그지 않음.

## 실행한 검증

- 기존 회귀 검사 11개 통과 (`work/verify.cjs`).
- 물리 단위 검사 22개 통과 (`node --test tests/physics.test.cjs`). 15/30/60/144FPS 동일 결과, 불규칙 dt, 점프 높이/공중 점프 금지, 고속 낙하·수평 이동, 벽·천장, 대각 이동, 직선/대각 가장자리 보호, 수영·비행·발판·불러오기 보정 포함.
- Chrome 브라우저 통합 21개 통과 (`node tests/browser.cjs`, Playwright 필요). 이전 저장 불러오기, 실제 키 입력과 마우스 잠금, E 선택창, 9칸 핫바/휠, 채굴/설치, 비행, 저장·재개·내보내기/가져오기, 손상 파일 거부, 수영, 안전 위치 복구, 리사이즈, 전체 화면 및 Keyboard Lock 허가/해제 검증. 콘솔/페이지 오류 0개. 결과는 `tests/browser-results.json`.
- Ctrl+W는 DOM 이벤트 매핑과 실제 Keyboard Lock API의 허가·해제를 검사했음. **물리 키보드에서 운영체제/브라우저 예약 단축키가 가로채지는지는 자동 검사하지 않았음.**
- 동일 1280×720 Chrome headless/ANGLE SwiftShader, 초기 작은 월드에서 115개 rAF 간격 샘플: 이전 평균 60.00FPS, p95 16.70ms; 변경 후 평균 59.99FPS, p95 16.80ms. 60Hz 제한에서 유의미한 FPS 향상은 입증되지 않음. 변경 후 샘플 시점에 16개 중 12개 청크와 선택 테두리 포함 13 Draw Call. 91,692개 정점은 그대로 유지. 실제 GPU·확장 월드의 60FPS를 보장하는 수치는 아님.
- 큰 테스트 월드를 통째로 가져오며 전체 재생성하는 구간에는 프레임 저하가 있음. 동적 월드 생성 작업의 분산은 4단계에서 처리할 사항.
